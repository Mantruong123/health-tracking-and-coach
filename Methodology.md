# 3. Methodology

This chapter details the technical implementation and architectural decisions behind the AuraFit ecosystem. It outlines the end-to-end system pipeline, the specific computer vision techniques used for pose estimation, the methods applied for real-time data smoothing, and the deterministic logic used to evaluate exercise form on mobile edge devices.
### 3.1 System Overview
The AuraFit ecosystem operates on a multi-tiered client-server architecture designed to balance computationally heavy artificial intelligence tasks with real-time responsiveness. The system pipeline consists of three main components: a mobile client, a backend intelligence API, and a web-based administrative dashboard. 

The mobile application (built with Flutter) serves as the primary user interface and the edge-computing hub. It accesses the smartphone camera, captures video frames, and processes them locally using Google ML Kit for pose estimation. This on-device processing guarantees real-time performance without the latency or privacy risks of cloud-based video transmission. The backend (FastAPI/PostgreSQL) handles persistent data storage, executes the logic for personalized nutrition and workout generation based on metabolic metrics, and processes premium upgrades via ZaloPay. The administrative dashboard (React) consumes backend endpoints to monitor user engagement and system health. This separation of concerns ensures that the tracking runs uninterrupted on the edge, while heavy data management relies on the cloud.

### 3.2 Pose Detection and Landmark Extraction
Before any exercise is classified, the raw video feed is processed to extract meaningful spatial representations. Each frame from the smartphone camera is converted into a structured input optimized for mobile inference. 

Google ML Kit’s Pose Detection API serves as the core feature extractor. For every processed frame, the model outputs a 33-point 3D skeletal landmark topology. Each landmark provides (X, Y) coordinates mapping to the 2D screen space, a Z coordinate representing depth (distance from the camera relative to the hips), and an *InFrameConfidence* score indicating the probability that the specific joint is visible and correctly identified. 

Instead of feeding raw pixel data to a classifier, the system relies on geometric calculations derived from these landmarks. The most critical features are the dynamic joint angles. For instance, the angle formed by the shoulder, elbow, and wrist landmarks defines the state of a bicep curl; the angle between the shoulder, hip, and knee defines back posture during a squat. These angle-based features are inherently scale-invariant, meaning the system can evaluate the user's form regardless of how close or far they stand from the camera.

### 3.3 Data Processing and Heuristic Smoothing
Because raw landmark coordinates generated by mobile computer vision models can be jittery due to motion blur, lighting changes, or partial occlusion, the extracted data must be smoothed before classification. Rather than using offline data augmentation to train a new model, this project applies real-time filtering techniques to stabilize the inference output.

An Exponential Moving Average (EMA) filter is applied to the key landmark coordinates across sequential frames. This reduces high-frequency noise (jitter) while maintaining responsiveness to actual bodily movement. Furthermore, the system implements a confidence thresholding mechanism: if the *InFrameConfidence* of a critical joint (e.g., the knee during a squat) drops below a predefined threshold, the frame is ignored to prevent false rep counting. Depth (Z-axis) coordinates are used selectively, as monocular camera depth estimation can be unreliable; instead, 2D planar angles are prioritized for exercises that occur parallel to the camera.

### 3.4 State Machine and Classification Logic
Since 3D skeletal data is already extracted with high fidelity, the system employs rule-based heuristic classifiers and Finite State Machines (FSM) rather than heavy neural classification heads to count repetitions and evaluate form. This approach is highly interpretable, requires minimal memory, and runs flawlessly on mobile hardware.

For each supported exercise, a dedicated state machine is defined. A standard repetition consists of transitioning through specific geometric states. For example, a push-up FSM requires the user to transition from an "UP" state (elbow angle > 160°) to a "DOWN" state (elbow angle < 90°) and back to the "UP" state. 

Simultaneously, secondary form-checking classifiers monitor parallel constraints. While the elbow angle dictates the push-up state, a separate check monitors the angle of the back (shoulder to hip to ankle). If the back angle deviates from a straight line beyond a defined tolerance margin, the system flags the repetition as invalid and triggers an immediate audio-visual warning (via Text-to-Speech) instructing the user to correct their posture. This dual-layered logic—one state machine for progression, one continuous monitor for form—functions as a deterministic ensemble, ensuring both accurate counting and safe exercising.
